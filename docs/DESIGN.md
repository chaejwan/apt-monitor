# apt-monitor 설계

관심 아파트 단지·평형·거래조건에 맞는 매물을 주기적으로 수집해 표와 지도로 보여주고,
매물 변화(신규·삭제·호가 변동)를 이력으로 남기며 텔레그램으로 알려주는 개인용 서비스.

## 0. 진단으로 바뀐 결정 (2026-10-18)

- GitHub Actions(해외 데이터센터 IP)에서는 `new.land`·`fin.land`·`m.land.naver.com`이 응답하지 않는다.
  네이버 메인·지도·`land.naver.com` 첫 화면은 열리므로 부동산 데이터만 골라 차단하는 것으로 보인다.
- KB부동산은 Actions에서 열리지만 매물 목록은 로그인해야 볼 수 있고(단지별 매물 수만 공개), 직방은 아파트 매물이 적다.
- 따라서 **네이버 매물 수집은 노트북(가정용 국내 IP)에서 Windows 작업 스케줄러로 실행해 결과를 push**한다.
  노트북이 꺼져 있는 동안은 수집이 비며, 켜지면 놓친 실행을 바로 한다.
- 실거래 수집, 화면(Pages), 이력 보관은 계획대로 GitHub에서 한다.
- 노트북에서도 브라우저 없이 부르면 429, 자동화 브라우저는 404 페이지로 돌려보낸다.
  **설치된 Chrome을 자동화 표시 없이 띄워 fin.land 페이지를 연 뒤, 그 페이지 안에서 `fetch`로 API를 부른다.**
- 확인된 API (`https://fin.land.naver.com/front-api/v1/...`, 로그인 불필요):
  - `GET complex?complexNumber=` 단지 정보 · `complex/pyeongList` 평형 · `complex/buildingList` 동·좌표 · `complex/article/stats` 거래유형별 매물 수
  - `POST complex/article/list` 매물 목록. 본문 `{"size":30,"complexNumber":3084,"tradeTypes":["A1"],"pyeongTypes":[],"dongNumbers":[],"userChannelType":"PC","articleSortType":"RANKING_DESC","lastInfo":[]}`,
    응답의 `lastInfo`를 넣어 다음 페이지. 항목마다 동·층·향·평형·호가·특징·확인일·중개사·좌표가 있고,
    같은 집을 여러 중개사가 올린 매물은 `duplicatedArticleInfo`로 묶여 온다. 입주가능일은 목록에 없다.

## 1. 전체 구조

```
[GitHub Actions]
  ├ 정기 실행 (KST 8·13·19시) ─▶ 네이버 매물 수집 → 이전 결과와 비교 → 이력 기록 → 텔레그램 알림
  ├ 매일 1회 ─────────────────▶ 국토부 실거래 수집 → 사라진 매물과 맞춰 보기
  └ 수동 실행 ────────────────▶ 지금 조회 / 단지 등록 (웹페이지 버튼에서 실행)
          │ 결과를 data/*.json 으로 commit
          ▼
[GitHub Pages 정적 페이지] ── JSON 읽기 ──▶ 표 + 카카오맵 + 이력 화면
          │ 조건 편집 / 지금 조회
          └─▶ GitHub API (내 브라우저에만 저장한 토큰)
```

- 서버 없이 GitHub만 사용한다. 저장소는 public이며 관심 단지와 이력이 공개되는 것을 감수한다.
- 수집기는 Python, 화면은 빌드 없는 HTML/JS + 카카오맵 JS SDK.

## 2. 데이터 소스

| 구분 | 출처 | 비고 |
|---|---|---|
| 단지 정보·평형·동·좌표 | 네이버 단지 API | 단지 등록 시 1회, 이후 주 1회 갱신 |
| 매물 목록 | 네이버 단지 매물 API | 거래유형과 평형으로 거르고 페이지를 넘기며 수집 |
| 입주가능일 | 네이버 매물 상세 | 새로 생긴 매물만 조회해 요청 수를 줄임 |
| 실거래 | 국토부 아파트 매매·전월세 실거래 API | 시군구 코드와 거래 월로 조회한 뒤 단지명·지번으로 연결 |

네이버는 비공식 API라 구조가 바뀌거나 해외(Actions) IP를 막을 수 있다. 0단계 진단(`수집 진단` 워크플로)으로 먼저 확인한다.

## 3. 핵심 설계 원칙

1. **매물 변화는 단지 단위로 판단한다.** 단지 전체 매물을 이전 결과와 비교한 뒤, 조건으로 걸러 이력에 남긴다.
   조건을 바꿔도 가짜 신규·삭제가 생기지 않으며, 실제 등록·삭제와 "조건진입/조건이탈"을 구분한다.
2. **삭제는 두 번 연속 보이지 않을 때만 판정한다.** 일시적인 수집 실패를 거래완료로 오인하지 않는다.
3. **같은 집 중복 매물을 묶는다.** 동·층·면적·가격이 같으면 하나로 보여준다.
4. **거래완료를 추정한다.** 사라진 매물과 같은 면적·층의 실거래 신고가 이후 들어오면 "거래 확인"을 표시한다.

## 4. 저장소 구조와 데이터 모델

```
collector/                # Python: 네이버·국토부 수집, 비교, 텔레그램 알림
config/watchlists.json    # 관심 조건 (웹페이지에서 편집)
data/
  complexes/{단지번호}.json   # 단지 정보, 평형·동 목록, 좌표
  listings/{단지번호}.json    # 매물 상태: 최초·최근 확인 시각, 가격 이력, 진행/삭제 상태
  trades/{단지번호}.json      # 실거래 기록
  events/YYYY-MM.jsonl        # 변화 이력 (월별, 한 줄에 한 건)
web/                      # GitHub Pages
probe/                    # 0단계 진단 스크립트와 결과
.github/workflows/        # collect.yml · trades.yml · probe.yml
```

관심 조건 (가격 단위: 만원):

```json
{ "id": "w1", "complexNo": "12345", "name": "○○단지",
  "areas": ["84A", "84B"], "tradeTypes": ["매매", "전세"],
  "price": { "매매": [100000, 130000] },
  "floor": { "excludeLow": 3, "excludeTop": false },
  "directions": ["남향", "남동향"], "dongs": [],
  "keywords": { "include": ["올수리"], "exclude": ["세안고"] },
  "moveInBefore": "2027-03", "notify": true }
```

이력 한 건:

```json
{"ts":"2026-10-18T13:05+09:00","watch":"w1","type":"가격인하","article":"2512345678",
 "dong":"103","floor":"12/25","before":125000,"after":122000}
```

이력 유형: `신규`, `삭제`, `가격인상`, `가격인하`, `조건진입`, `조건이탈`, `거래확인`.

## 5. 화면 구성

- **조건 목록**: 조건별 현재 매물 수, 최저가, 오늘 생긴 변화 개수.
- **매물 탭**: 표(동, 층, 향, 면적, 거래유형, 호가, 평당가, 입주가능일, 특징, 최초 등록일, 신규·가격인하 표시)와
  카카오맵(단지마다 마커 하나, 매물 수·최저가 표시, 누르면 동별 목록과 최근 실거래). 네이버 매물 좌표가 단지 단위라 지도는 단지 수준.
- **이력 탭**: 변화를 시간순으로 보여주고, 매물을 누르면 가격 변동 흐름을 표시.
- **실거래 탭**: 평형별 실거래가와 현재 최저 호가 비교, 전세가율.
- **단지 등록**: 네이버부동산 단지 주소를 붙여 넣으면 단지 등록 워크플로가 단지 정보를 가져오고,
  1~2분 뒤 평형·동 목록이 나타나면 조건을 설정한다. (브라우저에서는 CORS 때문에 네이버 API를 직접 부를 수 없음)

## 6. 정기 실행과 비밀값

- 정기 실행: `7 23,4,10 * * *` (UTC, KST 8:07·13:07·19:07). GitHub 정기 실행은 5~30분 늦을 수 있다.
- `concurrency: data-commit` 으로 데이터를 commit하는 워크플로가 동시에 돌지 않게 한다. 기록 commit은 `[skip ci]`.
- Secrets: `MOLIT_API_KEY`(공공데이터포털), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- 카카오맵 JavaScript 키는 설정 파일에 두고, 카카오 개발자 콘솔에서 사용 도메인을 `chaejwan.github.io` 로 제한한다.
- 웹 편집용 토큰: 이 저장소에만 contents·actions 쓰기 권한을 준 fine-grained 토큰을 브라우저 localStorage에만 저장한다.

## 7. 진행 단계

| 단계 | 내용 | 확인 기준 |
|---|---|---|
| 0 | 진단 워크플로로 Actions에서 네이버 응답 확인 | 매물 목록 JSON이 정상으로 받아짐 |
| 1 | 수집, 비교, 이력 기록, 텔레그램 알림 (조건은 파일로 직접 입력) | 신규·가격인하 알림이 옴 |
| 2 | Pages에 표, 지도, 이력 화면 | 휴대폰에서 확인 가능 |
| 3 | 실거래 수집, 거래완료 추정, 전세가율 | |
| 4 | 웹에서 조건 편집, 단지 등록, 지금 조회 | |

0단계에서 막히면 요청 간격·헤더를 조정해 재시도하고, 그래도 안 되면 매물 수집만 노트북에서 가끔 돌려 push하는 방식으로 바꾼다.
실거래, 화면, 알림은 그대로 GitHub에서 동작한다.
